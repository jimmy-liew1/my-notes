**SAML (Security Assertion Markup Language)** is an open-standard, XML-based framework for exchanging **authentication** and **authorization** data between an identity provider and a service provider.

In plain terms, it's the language that allows a user to log in to one service (like a corporate portal) and then automatically gain access to multiple other, independent services (like cloud applications) without having to log in again. This capability is known as **Single Sign-On (SSO)**.

***
## How SAML Works for Single Sign-On
SAML defines three main roles that work together to achieve SSO:
1. **The Principal:** This is the end-user (e.g., an employee) attempting to access a resource.
2. **The Identity Provider (IdP):** The system that authenticates the user. It stores the user's credentials, performs the login check, and asserts the user's identity. (e.g., Microsoft Entra ID/[[azure active directory|Azure AD]], Okta, Ping Identity).
3.  **The Service Provider (SP):** The application or resource the user is trying to access. It relies on the IdP to verify the user's identity. (e.g., Salesforce, Slack, or a corporate web app).

The process is essentially a secure handshake:
1. **User Requests Access:** The user tries to access a service provider (SP).
2. **SP Redirects to IdP:** The SP doesn't handle the login; it redirects the user's browser to the Identity Provider (IdP) for authentication.
3. **IdP Authenticates User:** The user logs in to the IdP (if they haven't already). Upon successful login, the IdP generates a secure document called a **SAML Assertion**.
4. **IdP Sends SAML Assertion:** The IdP sends the SAML Assertion (which is an XML document containing the user's identity, attributes, and authorization status) back to the user's browser, which then forwards it to the SP.
5. **SP Grants Access:** The Service Provider receives the assertion, verifies its digital signature to ensure it's from a trusted IdP and hasn't been tampered with, and finally grants the user access to the application.

***
## Benefits of Using SAML
SAML is widely adopted by enterprises because it offers significant advantages for both security and user experience:
* **Enhanced Security:** The SP doesn't have to store or manage user passwords, which reduces the security risk for the application. All credential management is centralized with the IdP.
* **Single Sign-On (SSO):** Users only have to remember one set of credentials, eliminating "password fatigue" and reducing calls to the IT help desk for password resets.
* **Centralized Control:** IT administrators can manage all user access and security policies (like multi-factor authentication) from a single IdP, ensuring consistent enforcement across all connected applications.
